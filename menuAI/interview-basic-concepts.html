最后一篇，回到大模型自己。temperature、topP、LoRA、RAG、幻觉——这些词你一定听过，但面试里要能「讲清楚为什么」，而不只是能「念出定义」。我们一个一个来。

15. temperature、topP、frequency penalty、presence penalty 各自含义？ ​

这四个是「生成控制旋钮」，决定模型怎么「选下一个词」。先建立共识：模型每次预测，是对词表里所有词算一个概率分布，然后按某种策略采样出下一个词。这四个参数就是在「概率分布」和「采样方式」上动手脚。

temperature（温度）：控制「随机性」。

  • 低温度（接近 0）：把概率分布「 sharpen 」，最可能的词概率被拉得极高，输出确定、保守、重复——像考试只写标准答案。
  • 高温度（比如 1.0+）：分布被「 flatten 」，冷门词也有机会被选中，输出发散、有创意、但可能胡来。

类比：temperature 是「发言激进度」。0 是照稿念，1.5 是即兴发挥可能跑题。

topP（核采样，Nucleus Sampling）：控制「候选池大小」。

它不按固定数量裁剪，而是：只从「累计概率达到 topP 的最小词集合」里采样。比如 topP=0.9，就把概率最高的词一路加，加到累计 90% 为止，只在这堆词里抽签，剩下的 10% 长尾直接丢弃。

类比：不固定取前 N 名，而是「取能覆盖 90% 选票的那些候选人」，人少的选区自动少取，人多的多取。比 topK 更灵活。

frequency penalty（频率惩罚）：惩罚「已经出现过的词」。

它是按出现次数线性加罚：一个词出现得越多，下次被选中的概率被压得越低。专门治「车轱辘话」——模型老重复同一个词时，这个参数能逼它换词。

presence penalty（存在惩罚）：惩罚「出现过这个事实」。

它不管出现几次，只要这个词出现过一次，就加一笔固定惩罚，鼓励模型去聊新话题、新概念。和 frequency 的区别：frequency 看「次数」（出现 5 次罚 5 倍），presence 看「有没有」（出现 1 次和 5 次罚一样）。一个治重复用词，一个治老绕一个话题。

16. 什么是 LoRA？优势是什么？ ​

LoRA = Low-Rank Adaptation（低秩适配）。它解决的核心痛点是：全量微调一个大模型太贵了——十亿、千亿参数全训一遍，显存、时间都扛不住。

LoRA 的巧思：不改原模型权重，而是在旁边加两个又瘦又小的小矩阵 A、B（秩 r 很小，比如 8、16、64），让它们去学习「原模型的增量」ΔW ≈ B×A。训练时只训这两个小矩阵，参数量可能只有全模型的 0.1%~1%。

优势一条条数：

  1. 省显存：不用存全模型梯量和优化器状态，训练开销骤降，消费级显卡也能玩微调。
  2. 训练快：要更新的参数少，迭代飞快。
  3. 可插拔：原模型纹丝不动，一个底座能挂多个 LoRA（一个管「写诗风」、一个管「客服风」），切换时只换小矩阵，不重新加载大模型。
  4. 不易灾难性遗忘：原权重锁死，新知识只加在增量上，不会把旧能力冲掉。

类比最直观：原模型是一栋精装房，全量微调是砸墙重装；LoRA 是贴墙纸、摆家具——风格想换就换墙纸，房子本身不动，省钱还可逆。

17. 什么是 RAG？解决什么问题？ ​

RAG = Retrieval-Augmented Generation（检索增强生成）。

流程一句话：模型回答之前，先从外部知识库检索相关资料，把资料拼进提示词，再让模型基于这些资料生成答案。

它解决三个大模型天生的病：

  • 知识时效性：模型训练完，世界还在变。RAG 让它能查「最新文档」，不用重训就能用上新知。
  • 幻觉：凭空编是模型老毛病，给它「证据」摆在眼前，它更可能照着说，而非瞎编。
  • 私有数据：公司内网、个人笔记这些没进训练的数据，RAG 不用把数据喂进模型，也能让模型「基于它回答」，隐私友好。

类比：开卷考试。闭卷（纯模型）靠记忆，记错就错、没学的就不会；开卷（RAG）允许你翻书——翻开相关页，照着答，又准又能溯源。

18. 什么是模型幻觉？怎么缓解幻觉？ ​

幻觉 = 模型一本正经地编瞎话：事实错误、张冠李戴、引用根本不存在的论文、编造从未发生的对话。注意它「自信满满」——不像 bug 那样报错，而是流利地错。

为什么会产生？根子在两处：一是训练数据本身有噪声 / 冲突；二是自回归生成本质是「按概率接龙」，当它在某个知识点上概率分布模糊，就会「编一个最像真的」出来，而不是说「我不知道」。

缓解手段，从根到表：

  1. RAG 给证据：让回答有资料兜底，模型照着说，瞎编空间变小（上一题已讲）。
  2. 对齐训练 / RLHF：用人类反馈压低「胡说」的倾向，教它「不确定的事别硬编」。
  3. 提示约束：明确告诉它「不知道就直说，不要编造」，限定领域、要求引用来源。
  4. 工具校验：需要精确事实时，让模型去调搜索 / 数据库 / 计算器核对，而非凭记忆。
  5. 降低 temperature：温度越高越爱发挥，关键事实场景调低，输出更稳。
  6. 后处理事实核对：生成后用另一道校验（规则 / 小模型 / 知识图谱）过滤明显错误断言。

一句话总结这一篇：四个旋钮管「怎么选词」；LoRA 是给大模型贴墙纸式的便宜微调；RAG 是开卷考试治时效与幻觉；幻觉靠证据 + 约束 + 工具 + 低温度组合拳缓解。
