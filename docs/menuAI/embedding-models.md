# Embedding 模型详解：从 text-embedding 到 BGE

## 一句话理解 Embedding

Embedding 说白了就一件事：**把文字、图片、声音这些东西，翻译成一串数字（向量）**。

为啥要翻译？因为计算机不识字，它只识数。你给模型一篇博客、一段对话、甚至一张猫的照片，模型内部第一步就是把它变成向量，然后在向量空间里做各种运算。

你可以把 Embedding 想象成一个"语义坐标系"——意思相近的东西，坐标离得近；意思不搭边的东西，坐标离得远。

比如"苹果手机"和"iPhone"，翻译成向量后几乎挨在一起；而"苹果手机"和"香蕉"，隔了十万八千里。

## 从 One-Hot 到稠密向量：Embedding 的进化

### One-Hot：最原始的"身份证"

早期的做法叫 One-Hot 编码。假设你有一本词典，里面有一万个词，每个词就分配一个一万维的向量。"苹果"是 `[1, 0, 0, 0, ...]`，"香蕉"是 `[0, 1, 0, 0, ...]`。

这相当于给每个词发了一张"唯一身份证"——每个词都不重复，但完全看不出任何语义关系。

苹果和香蕉明明都是水果，在 One-Hot 编码里，它们的向量夹角永远是 90 度，毫无关联。

### Word2Vec：第一次让机器"理解"语义

2013 年，Word2Vec 横空出世，第一次让向量有了语义。

它的核心思想很简单：**上下文相似的词，意思也相似**。如果一个词经常出现在"猫""狗""兔子"旁边，那它大概率也是个动物。

Word2Vec 训练时玩一个"填空游戏"：给定一句话，遮住中间一个词，让模型猜这个词是什么。猜着猜着，模型就学会了——"国王"和"女王"的向量差，约等于"男人"和"女人"的向量差。

这就是著名的 **King - Man + Woman ≈ Queen**。

Word2Vec 把一万维的稀疏向量压缩成了几百维的稠密向量，而且语义相近的词真的会聚在一起。

但 Word2Vec 有个硬伤：**一个单词只能有一个向量**。比如"苹果"既可以指水果，也可以指公司，Word2Vec 只能给出一个"折中"的向量，无法区分语境。

### 上下文感知 Embedding：BERT 的时代

2018 年 BERT 出来了，解决了这个问题。

BERT 的思路是：**同一个词，在不同句子里，向量应该不一样**。

"我今天吃了个苹果"和"苹果发布了新 iPhone"，两个"苹果"被 BERT 编码后，向量完全不同。因为 BERT 在编码每个词时，会同时"看"这个词前后所有的词，根据上下文动态调整输出。

你可以理解为：Word2Vec 是"查字典"，每个词固定对应一个释义；BERT 是"读上下文"，根据语境判断意思。

今天的 Embedding 模型，基本都沿用了 BERT 这种"上下文感知"的架构。

## Embedding 模型是怎么工作的？

### 编码流程：从文本到向量

一个现代的 Embedding 模型（比如 BGE、text-embedding-3）处理文本的流程大概是这样的：

**第一步：分词（Tokenization）**

把句子拆成模型认识的小块。"Embedding 模型很厉害"可能被拆成 `["Embed", "ding", " 模型", " 很", " 厉害"]` 这样的 Token 序列。

**第二步：嵌入层（Embedding Layer）**

每个 Token 先变成一个基础向量。这一步有点像查表——模型内部有一张"词向量表"，每个 Token 对应一个初始向量。

**第三步：上下文编码（Transformer Encoder）**

这是最关键的一步。模型把整句话的所有 Token 向量一起送入 Transformer Encoder，通过 Self-Attention 机制让每个词"看到"其他所有词，然后根据上下文重新调整自己的向量。

**第四步：池化（Pooling）**

模型输出的是每个 Token 的向量，但我们需要的是整句话的向量。怎么办？

最常见的做法是**均值池化**——把所有 Token 向量加起来取平均。也有模型直接用 `[CLS]` 这个特殊 Token 的向量作为句子表示，或者取最后几层的加权平均。

最后出来的向量通常有 768 维、1024 维甚至更高。这就是这段话的"语义坐标"。

### 对比学习：让相似句子更近，不相似句子更远

 Embedding 模型怎么知道自己编得对不对？答案是**对比学习**。

训练时，模型会收到一批"句子对"。有些是正例（意思相近），比如"今天天气很好"和"阳光明媚的一天"；有些是负例（意思无关），比如"今天天气很好"和"量子力学很难懂"。

模型的目标就是让正例对的向量距离尽量小，负例对的向量距离尽量大。

你可以想象成在球场上安排站位：让队友站得近，让对手站得远。训练就是在不断优化这个"站位"。

## 维度选择：Embedding 该多"长"？

Embedding 向量的维度，就是这组数字的个数。常见的有 384 维、512 维、768 维、1024 维，甚至 4096 维。

维度越高，能表达的语义信息越丰富，但存储和计算成本也越高。怎么选？

### 低维度（256~384 维）：轻量快速

适合对速度要求高、数据量不大的场景。比如前端做语义搜索、客户端本地匹配。BGE 系列有专门的轻量版（BGE-small），就是 384 维，在浏览器里跑都没问题。

类比一下：低维 Embedding 像是用"身高、体重、年龄"三个标签描述一个人。信息少，但查询快。

### 中维度（512~768 维）：平衡之选

这是目前最常用的区间。OpenAI 的 text-embedding-3-small 是 1536 维（但支持降维），BGE-base 是 768 维。

在大多数 RAG 场景下，768 维已经足够把语义区分得很细了。

### 高维度（1024~4096 维）：追求极致

适合需要非常精细语义区分的场景，比如跨语言检索、法律/医学等专业领域。BGE-large 是 1024 维，能捕捉到更微妙的语义差别。

但要注意：**维度越高，向量数据库的存储和搜索成本指数级增长**。不是越高越好，够用就行。

### 一个实用的经验法则

如果你不确定选多少维，可以这么考虑：

- **万级数据量** + **简单语义匹配** → 384 维够了
- **百万级数据量** + **RAG 检索** → 768 维是甜点
- **千万级以上** + **跨语言/专业领域** → 1024 维或更高

还有个技巧叫**Matryoshka Embedding（俄罗斯套娃 Embedding）**。这种模型在训练时会让不同维度的前缀都能独立表达语义。比如一个 768 维的向量，你取前 256 维也能用，前 512 维效果更好，全用 768 维效果最好。这样你可以在存储时按需截断，非常灵活。

## 多语言 Embedding：跨语言的"通用语"

如果你的用户既说中文又说英文，甚至还说日语、法语，那 Embedding 模型必须支持多语言。

### 多语言模型是怎么做到的？

核心思路是**对齐（Alignment）**：让不同语言中意思相同的句子，在向量空间里落在同一个位置。

比如"苹果很好吃"（中文）和"Apples are delicious"（英文），经过多语言 Embedding 模型编码后，它们的向量几乎一样。

训练时，模型会接触大量的"平行语料"——同一内容的不同语言版本。通过对比学习，模型学会了"翻译无关，语义有关"：不管用什么语言表达，只要意思一样，向量就近。

### 主流多语言 Embedding 模型

**BGE-M3** 是目前非常强的多语言 Embedding 模型，支持 100+ 种语言。它不仅能做语义检索，还能处理稀疏表示（关键词匹配）和稠密表示（语义匹配），所以叫"M3"——Multi-Functionality、Multi-Linguality、Multi-Granularity。

**text-embedding-3** 系列（OpenAI）也是多语言的，但闭源，按 Token 收费。

**E5-multilingual**（微软）是开源的多语言模型，效果也不错。

如果你的应用只需要处理中文和英文，BGE 系列几乎是不二之选；如果需要覆盖小语种，BGE-M3 的性价比很高。

## Embedding 模型的选型建议

前端/全栈同学在实际项目中怎么选 Embedding 模型？给你几个实用建议：

**1. 先看语言**

纯中文场景 → BGE-base-zh、BGE-large-zh
中英混合 → BGE-M3、E5-multilingual
多语言 → BGE-M3、text-embedding-3-large

**2. 再看规模**

小项目/本地跑 → BGE-small（384 维，轻量）
中型 RAG → BGE-base（768 维，平衡）
大型生产 → BGE-large（1024 维）或闭源 API

**3. 最后看成本**

开源模型（BGE、E5）可以本地部署，没有调用费用，但要自己准备 GPU 或 CPU 资源。

闭源 API（OpenAI、Cohere）按 Token 收费，省心但长期成本高。

**4. 一个冷知识**

Embedding 模型和生成模型是两条赛道。ChatGPT 生成文字很强，但它的 Embedding 能力未必比专门的 Embedding 模型好。做 RAG 时，检索阶段用专门的 Embedding 模型（如 BGE），生成阶段用大模型（如 GPT-4），这是最优组合。

## 小结

Embedding 是 AI 应用的"地基"。不管是 RAG 检索、语义搜索、推荐系统还是文本分类，底层都在做同一件事：**把语义变成坐标**。

理解 Embedding，关键是记住三点：

1. **它是语义的空间映射**——意思近，坐标近。
2. **现代 Embedding 是上下文感知的**——同一个词在不同句子里，向量不一样。
3. **维度不是越高越好**——根据数据量和精度需求选，768 维是大多数场景的甜点。

下一篇我们会聊 RAG 的"二次筛选"——重排序（Reranking）。如果说 Embedding 检索是海选，那重排序就是复赛，它的作用是让最相关的结果真正排在最前面。
