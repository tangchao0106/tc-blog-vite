# FlashAttention：让注意力计算"省显存又提速"

很多人第一次听到 FlashAttention，会以为这是个"模型"或者"新架构"。说白了，它既不是新模型，也不是换了套算法，而是**把原有的注意力计算"重新排了个序"**——同样的数学公式，换一种更聪明的执行方式，显存占用直接砍掉一大半，速度还能翻倍。

打个比方：你要在图书馆读完一本 1000 页的书并做摘要。笨办法是把整本书逐页摊在超长的大桌子上（省事但占地方），每看一页就去大桌子找对应内容；聪明的办法是搬把小凳子，一次抱一摞书在膝盖上快速翻完、记好笔记，再换下一摞。小凳子空间有限，但你全程没把整本书摊开，反而更快更省地读完了。FlashAttention 干的就是这个"搬小凳子、分批读、边读边记"的活儿。

## 先说痛点：标准 Attention 的"显存墙"

要理解 FlashAttention，得先知道标准注意力计算卡在哪。

经典 Self-Attention 里，模型会算出一个 N×N 的"注意力分数矩阵"（N 是序列长度，也就是 Token 数量）。这个矩阵意味着：序列每多一个 Token，这个方阵就按平方级膨胀。比如 1000 个 Token，是 100 万个数；10 万个 Token，就是 100 亿个数。这是个**平方级（O(N²)）的显存灾难**。

更麻烦的是，GPU 干活的真实瓶颈往往不是算力，而是**搬数据**。GPU 有两大块存储：一块是算力核心旁边的 SRAM（很小、极快，像你手边的草稿纸），一块是板载的 HBM 显存（很大、较慢，像远处的仓库）。标准做法要把那个巨大的 N×N 矩阵从仓库（HBM）读到草稿纸（SRAM）里算，算完再写回仓库——来来回回搬了好几趟，绝大部分时间都花在"搬货"而不是"算账"上。

想象一条流水线：工人算力很强，但原材料放在 100 米外的仓库，每道工序都得跑过去取一趟再跑回来。工人大部分时间在跑步，而不是干活。这就是标准 Attention 的真实写照。

## FlashAttention 的核心：分块 + 不落地的计算

FlashAttention 的解法其实很朴素，分两招：

**第一招，分块（Tiling）。** 它不一次性把整个 N×N 大矩阵搬出来，而是把它切成很多小块（tile），每次只搬一小块进 SRAM 里算。这样 SRAM 那点"草稿纸"大小就够了，根本不需要把整张巨表摊开。

**第二招，在线 softmax（Online Softmax）。** 这是最巧妙的地方。Softmax（把分数变成 0~1 的概率分布）本来需要"看到所有分数"才能算——因为分母是所有分数的求和。但 FlashAttention 用了一个数学技巧：每读入一小块，就增量地更新"运行总和"和"最大值"，边读边把概率归一化掉，永远不需要把整行分数都存着。等所有块读完，结果已经算好了，中间的大矩阵从头到尾**根本没在显存里完整存在过**。

你可以理解为：考试时老师不让你把整张草稿纸交上去，只收最终答案。FlashAttention 就真的"只在脑子里打草稿，不写在纸上"，算完直接给答案，那张铺天盖地的草稿纸（N×N 矩阵）压根没生成。**这就是它省显存的根本原因——靠的是"重计算"（recomputation），宁可反向传播时多算一遍，也不存中间结果。**

## 为什么又快

快的根源同样在"少搬货"。因为分块后所有计算都在 SRAM 里完成，GPU 不再频繁往返 HBM 仓库搬那个大矩阵。SRAM 的带宽比 HBM 高出一个数量级，相当于把"100 米外的仓库取货"变成了"手边拿东西"。算力被真正用在了刀刃上，而不是浪费在搬运上。

一张图记住它：左边是标准 Attention——HBM 里躺着一张巨大的 N×N 矩阵，数据在 HBM 和 SRAM 之间反复横跳；右边是 FlashAttention——小块数据进 SRAM，算完即弃，HBM 里干干净净。**显存从 O(N²) 降到 O(N)，速度随序列长度几乎线性提升。**

## 对你（前端/应用开发者）意味着什么

你大概率不会自己去实现 FlashAttention——那是框架底层的事。但它实实在在地影响着你的体验：

- **更长的上下文变便宜了。** 以前长文档处理因为显存爆炸跑不动，现在 FlashAttention 让长序列推理成为日常。你做的"上传一份 200 页 PDF 让 AI 总结"，背后就有它的功劳。
- **推理延迟更低、成本更低。** 同样的卡能跑更长的序列、更高的吞吐，供应商成本下降，最终体现在 API 价格和你用户的等待时间上。
- **它已经是"默认选项"。** vLLM、SGLang、PyTorch 原生、各大推理框架几乎默认开启 FlashAttention（或它的变体 FlashAttention-2/3、以及 PagedAttention 等结合版本）。你选型框架时，认准"支持 FlashAttention"基本是标配，不用特别操心。

一句话总结：**FlashAttention 没改变注意力的"数学道理"，却重写了它的"执行剧本"。** 它用分块计算 + 在线 softmax + 重计算，把显存从平方级压成线性级，让长上下文和高吞吐从"奢侈品"变成"日用品"。下次听到模型"支持超长上下文"，你就知道，幕后那位搬小凳子、边读边记笔记的"图书管理员"，叫 FlashAttention。
