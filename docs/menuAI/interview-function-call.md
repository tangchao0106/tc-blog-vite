大模型「会聊天」已经不够看了，现在面试必问「它怎么干活」——也就是 Function Call（函数调用 / 工具调用）。这一篇把三个最容易卡壳的问题讲透。

## 10. 大模型是怎么知道该调用哪个函数的？完整流程是什么？

先破除一个迷思：**模型本身并不会真的去执行任何函数**。它做的一件事，是「输出一段结构化的描述，告诉你的程序：我想调哪个函数、参数是什么」。真正干活的是你写的代码。

完整流程画成图是这样的：

1. **登记工具**：你先把所有可用函数写成一份「说明书」（JSON Schema），包含函数名、干什么用、每个参数是什么类型、哪个必填。这份说明书被塞进系统提示（system prompt）。
2. **用户提问**：比如「帮我把今天的销售数据存到数据库」。
3. **模型判断**：模型读完说明书 + 用户问题，觉得「这事儿得调 `save_to_db` 函数」，于是它不直接回答，而是输出一段工具调用指令，形如 `{ "name": "save_to_db", "arguments": { "table": "sales", "data": "..." } }`。
4. **程序执行**：你的代码解析这段指令，真去调用 `save_to_db`，拿到返回结果（成功 / 报错 / 数据）。
5. **回填上下文**：把「函数执行结果」作为新消息，塞回对话历史，再喂给模型。
6. **模型总结**：模型看到结果，用自然语言告诉你「已保存，共 128 条」。

类比特别形象：**模型是调度员，只写派工单；你写的代码是工人，拿着派工单去现场干活，再把回执交回调度员**。模型从头到尾没碰过数据库，它只是很会「安排活儿」。

所以「怎么知道调哪个」的答案就是：**靠你在提示里给的函数说明书 + 模型自身的语言理解能力，它从说明书里挑最匹配的那个，并把参数填进结构化输出。** 不是模型真的「知道」函数内部逻辑，而是它学会了「看到某类问题，就对应输出某份派工单」。

## 11. 模型输出函数调用，但缺少必填参数，该如何处理？能不能程序自动补参数？

现实里模型经常「忘填参数」。比如调 `query_weather(city)`，`city` 是必填，它却只输出 `{ "name": "query_weather", "arguments": {} }`。

处理思路分三档：

1. **回炉重造（最稳）**：把「你少填了必填参数 city」这条提示，作为新消息塞回对话，让模型意识到缺东西。模型通常会二选一：要么反问用户「请问查哪个城市？」，要么从对话上下文补上（比如上文用户说过「北京」，它就填上 "Beijing"）。
2. **用默认值兜底（限有 default 的）**：如果 Schema 里 `city` 标了 `default: "Beijing"`，程序可以直接填默认值，不折腾模型。
3. **前端收集（涉及隐私/外部输入）**：缺的是用户专属信息（比如 `user_id`），模型根本不可能知道，这时别硬编，老老实实弹个表单让用户填，或从头像 / 登录态里取（session 里本来就有 userId，直接程序注入，不算「模型编」）。

**能不能程序自动补？** 要分情况：

- 能自动补的：**有明确来源的参数**。比如 `user_id` 从登录态拿、`timestamp` 用当前时间、`session_id` 从上下文取。这些是「程序本来就掌握的事实」，直接注入完全合理。
- **不能自动补的**：模型缺失的是它本该从问题里推断的业务参数（比如用户没说城市），程序**绝不能凭空编造**一个城市塞进去——那会产出错误结果，且极难排查。这种只能反问或报错。

一句话：**程序只补「自己确实知道」的参数；模型该问用户的，就让它去问。**

## 12. 需要先后调用两个有依赖关系的工具，是一次性输出两个调用，还是分步调用？为什么？

结论：**有依赖就分步调用，不要一次性输出两个。**

原因很朴素：第二个工具的参数，要靠第一个工具**跑出来的结果**才能确定。模型在「写派工单」的那一刻，第一个工具还没执行，结果根本不存在，它只能瞎猜第二个的参数——猜错就全盘皆输。

正确姿势是一问一答地串：

1. 模型输出第一个调用，比如 `get_city_id("北京")`。
2. 程序执行，返回 `city_id: 12345`。
3. 把 `12345` 回填上下文。
4. 模型这下「看见」了 city_id，才输出第二个调用 `get_forecast(city_id=12345)`。
5. 程序执行，返回预报，模型总结。

类比：你要先问「北京的城市编码是多少」拿到编号，再用编号去查「这个城市未来三天的天气」。你不可能两张派工单同时下——第二张单子上「城市编号」那一栏，在第一步完成前是空白的。

有些框架支持「并行调用」（parallel tool calls），那是**给没有依赖关系的多个工具用的**——比如同时查「北京天气」和「上海天气」，两者互不依赖，可以一并输出、并发执行省时间。判断标准就一条：**B 的输入是否来自 A 的输出？是 → 分步；否 → 可并行。**
